## TL;DR

- The site has two topics. **About Basel** answers about Basel, the projects and freelance work. Its panel is the project grid, now called **Projects** (owner's pick over Work and Portfolio). **About This System** is unchanged; its panel is the diagram.
- **Phones (owner's option A):** the topic owns its view. The switch is Chat | Projects under About Basel and Chat | Diagram under About This System. The stress test jumps to This System › Diagram.

## What changed for a visitor

- **Project cards** ask "Tell me about <title>" in About Basel, and typed project questions work there too.
- **Links:** old `?topic=portfolio` links open About Basel with its grid. A saved Portfolio conversation is dropped.
- **Footer:** "See projects →".
- **Suggestions:** About Basel adds "What projects have you built?". The three Portfolio suggestions are retired, including the freelance one.

## How it works

```
question (About Basel) ──> worker: FT.SEARCH @corpus:{about_me|portfolio}
                              │  retrieval-cache version = ver(about_me) + ver(portfolio)
                              ▼
prompt v22: [n] About Basel (projects · <section>): ...
            [n] portfolio project (GoalBuddy · <section>): ...   (never planned-marked)
            + "a fact from one project's source belongs only to that project ..."
```

**Frontend:** `lib/topics.ts` holds `panelView(topic)`, `topicForView(view)` and `initialTopic(...)`. `App.tsx` applies them in three places: each view change goes through `followView`, a safety effect switches a mismatched phone panel in place, and the stress tap uses it too.

## Key decisions and trade-offs

- **Backend first.** The backend is harmless on its own; the frontend would have regressed typed portfolio questions if it had shipped alone.
- **Rollout guard.** The worker reports `retrieval_mode`, and the API won't cache an answer an older worker built. That stops About Basel answers without project content from being cached during a rollout.
- **Index unchanged.** The `portfolio` ingest corpus stays as it is: no re-ingest, no migration. The API still accepts `corpus=portfolio`; removing it is a cleanup item.
- **Saved Portfolio chats are dropped, not merged.** A merge would interleave two conversations the visitor never had together.
- **More decisions** are listed in BACKLOG, "Two topics: About Basel absorbs Portfolio".
