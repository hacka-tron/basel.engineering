## Review findings (Claude, this checkpoint) — must fix before Phase 2 is complete

1. **Critical — no embedding-model isolation in the live retrieval index.** `services/glassbox/ingest/redis_index.py`'s `idx:chunks` schema and `services/glassbox/retrieval/search.py`'s `search_chunks()` have no model tag/filter, only `corpus`. Ingestion swallows exceptions per document before reaching the vector write, so a partial re-ingestion failure (a real, already-observed failure mode in this project — Bedrock throttling, `ResourceNotFoundException`) leaves an old-model vector live and silently mixed into KNN search for that corpus, indistinguishable from current-model vectors. This is exactly what the Phase 2 plan said not to allow. Fix: tag chunk records with their embedding model (mirroring what `RedisAnswerCache` already does correctly) and filter `search_chunks()` by the current provider's `model_id`, or make ingestion fail closed on any per-document embedding failure during a model switch rather than continuing.
2. **Important — answer-cache stampede is real and untested for real concurrency.** No lock between the cache-miss check and the cache write in `services/glassbox/api/ask.py`; two truly concurrent requests for the same new question both pass the miss check and both trigger a real paid LLM call. The existing "concurrent" test (`test_answer_cache.py`) issues two *sequential* calls, not concurrent ones (unlike the rate-limiter test, which correctly uses `asyncio.gather`). Fix: a short-TTL `SET NX` lock keyed by `(corpus, corpus_version, model_id, normalized_question)` around the miss-then-generate path, plus an actual concurrent test using `asyncio.gather`.
3. **Important — no startup validation despite the plan requiring it.** `services/glassbox/api/main.py` has no startup/lifespan hook checking provider config; a malformed `GLASSBOX_PROVIDER`/model ID passes health checks and only fails on the first real request. Fix: add a startup hook that constructs and sanity-checks the configured providers.
4. **Important — confirmed real hallucination, root cause identified.** `_prompt()` in `services/glassbox/api/ask.py` (and the grounding rules in `services/glassbox/providers/bedrock.py`) has no instruction distinguishing current vs. planned/future functionality. `docs/DESIGN-003-ingestion.md` describes the not-yet-built Google Drive connector in plain declarative prose, which is exactly what got cited as current. Fix: add an explicit instruction (e.g. "only describe something as currently working if the source states it exists today; flag anything described as planned/future/roadmap explicitly").
5. Two minor suggestions, lower priority: `client_ip_hash` shares one rate-limit bucket for all clients when `request.client` is `None`; there's no signal distinguishing daily-budget slots spent on real answers vs. spent-then-failed generations.

Next action: fix findings 1–4 (in a worktree, per the new `CODEX.md` policy), re-verify live, then Phase 2 can be marked complete in `SNAPSHOT.md`/`BACKLOG.md`.
